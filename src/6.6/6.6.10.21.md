# Release notes Shopware 6.6.10.21

## Abstract

This release closes 11 issues, focused on checkout payment rules, Store API session handling, storefront link categories, and ZUGFeRD correction documents. It also updates dompdf to 3.1.6 to resolve open advisories and fixes two administration issues around list filters and document downloads after bulk edits.

## System requirements

* tested on PHP 8.2 and 8.4
* tested on MySQL 8 and MariaDB 11

## Improvements

(No notable improvements in this patch release)

## Fixed bugs

* Updated the PDF rendering library dompdf to 3.1.6 to clear open security advisories ([#18597](https://github.com/shopware/shopware/issues/18597))
* Payment methods with "Allow payment change after checkout" disabled can no longer be used to pay an existing order through the Store API — previously the setting only filtered the admin UI, so methods with their own JavaScript payment button (e.g. PayPal smart buttons) slipped through ([#17495](https://github.com/shopware/shopware/issues/17495))
* Store API requests no longer trigger session initialization, which caused unnecessary session storage growth and could hold PHP session locks; storefront sessions and customer imitation are unaffected ([#18319](https://github.com/shopware/shopware/issues/18319))
* Categories of the type "link" now redirect to their target instead of running into an error page in the storefront ([#18154](https://github.com/shopware/shopware/issues/18154))
* ZUGFeRD correction and cancellation invoices now handle shipping costs correctly: refunded shipping is written as an allowance, charged return shipping as a charge, and zero-value shipping produces no delivery node at all ([#18095](https://github.com/shopware/shopware/issues/18095))
