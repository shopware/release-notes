# Release notes Shopware 6.6.10.32

## Abstract

This patch release contains security fixes. Please update to this patch release as soon as possible. If you cannot update immediately, it is highly recommended to use the [Security Plugin](https://store.shopware.com/en/swag136939272659f/shopware-6-security-plugin.html).

Shopware 6.6.10.32 is a security-focused patch release with fixes for 11 security advisories, including SQL injection, XML external entity injection, stored cross-site scripting, and several authorization and information-disclosure issues. It also closes 40 issues, with corrections for order and checkout flows, canonical URLs and sitemaps, e-invoice documents, and Storefront accessibility at large text sizes. Shop operators should update as soon as possible.

## System requirements

* tested on PHP 8.2 and 8.4
* tested on MySQL 8 and MariaDB 11

## Improvements

(No notable improvements in this patch release)

## Fixed bugs

* Fixed order recalculation in the Administration using the customer's default address instead of the order's own shipping address, which could wrongly make orders tax-free ([#22497](https://github.com/shopware/shopware/issues/22497))
* Fixed failed payments during checkout showing a 400 error page instead of redirecting customers to the edit-order page ([#22466](https://github.com/shopware/shopware/issues/22466))
* Fixed missing main navigation, footer navigation and payment/shipping logos on full CMS pages such as the revocation page ([#22479](https://github.com/shopware/shopware/issues/22479))
* Fixed ZUGFeRD/XRechnung cancellation invoices for orders with promotions being rejected by the KoSIT validator ([#22492](https://github.com/shopware/shopware/issues/22492))
* Fixed out-of-stock variants that inherit "Clearance sale" from their parent being dropped from the sitemap, which could remove the whole product ([#22512](https://github.com/shopware/shopware/issues/22512))
