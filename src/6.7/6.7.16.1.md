# Release notes Shopware 6.7.16.1

## Abstract

This patch release contains security fixes. Please update to this patch release as soon as possible. If you cannot update immediately, it is highly recommended to use the [Security Plugin](https://store.shopware.com/en/swag136939272659f/shopware-6-security-plugin.html).

This release closes 9 issues, mostly around security, tooling and test reliability. MCP endpoints get stricter origin checks through the SDK 0.9 update, with a new `shopware.mcp.allowed_origins` option to allow additional origins. Smaller corrections cover UUID generation, Composer and static analysis, and flaky CI jobs.

## System requirements

* tested on PHP 8.2, 8.4 and 8.5
* tested on MySQL 8, MySQL 9.7, MariaDB 11 and MariaDB 12

## Improvements

(No notable improvements in this patch release)

## Fixed bugs

* Updated the MCP SDK to 0.9 and the MCP bundle to 0.15 to close a security advisory. Browser-based MCP clients on origins other than the shop's own now need an entry in the new `shopware.mcp.allowed_origins` option ([#22805](https://github.com/shopware/shopware/pull/22805))
* Fixed Composer installs and updates failing because of the low-severity `mcp/sdk` security advisory ([#22738](https://github.com/shopware/shopware/pull/22738))
* Replaced deprecated ramsey/uuid binary helpers in UUID generation, so version and variant bits are set directly ([#23028](https://github.com/shopware/shopware/pull/23028))
* Pinned `phpdoc-parser` to 2.3.6 to stop 140 static-analysis errors caused by an incompatibility with PHPStan 2.3.1 ([#23036](https://github.com/shopware/shopware/pull/23036))
* Fixed rate limiter tests that failed after a `symfony/rate-limiter` update changed how the retry time is rounded ([#23035](https://github.com/shopware/shopware/pull/23035))
